# M0 | Save and digest

Status on 2026-10-17: all M0 checks pass. Save and digest work end to end
through the private Telegram bot.

## How it works

```
Telegram app -> Telegram servers <- bot.py (long polling)
                                      |
                                      v  POST /save
                                   api.py -> SQLite (saved_items)
                                          -> fetch_url (article page)
                                          -> digest (OpenAI, JSON mode)
```

- `bot.py` only accepts messages from the configured owner ID, sends the text
  to `POST /save` and replies with the result. It has no business logic.
- `/save` saves the row first, fetches only when there is no text yet, and
  calls the model only when there is text but no digest yet. A digest failure
  returns 200 with `status: digest_failed`; the fetched text is kept.

## Setup

1. Python 3.12+ virtual environment:
   `python3.12 -m venv .venv && source .venv/bin/activate`
2. `pip install -r requirements.txt`
3. Copy `.env.example` to `.env` and fill in:
   - `OPENAI_API_KEY`, `OPENAI_MODEL` (we use `gpt-4o`)
   - `TELEGRAM_BOT_TOKEN` (from @BotFather, `/newbot`)
   - `ACCEPT_BOT_FROM_ID` (your Telegram user ID: send the bot any message,
     then read `message.from.id` from `getUpdates`)
   - optional `READLATER_DB` (default `data/readlater.db`)
4. Terminal 1: `uvicorn api:app --app-dir src --reload`
5. Terminal 2: `python src/bot.py`
6. Send a link to the bot. Expected reply: `Saved: <title>`, summary and tags.

Offline tests: `pytest` (no network, no API key needed).

## Unexpected failures

### 2026-10-17: Fowler article digest always failed

- What happened: `martinfowler.com/articles/microservices.html` was saved and
  fetched (42,874 chars), but the digest failed with `invalid_json` every time.
  The bot also sent no reply, because it checked for `"digested_failed"`
  instead of `"digest_failed"` and had no fallback branch.
- Cause 1: without JSON mode, the model sometimes wraps the JSON in a
  ```json block. The 10/12 eval had already shown this (prompt-only 2/5), but
  the JSON-mode setting was not carried into `model.py` on 10/15.
- Cause 2: after turning on JSON mode, OpenAI returned 400:
  "Response input messages must contain the word 'json'". The word was only in
  `instructions`, not in `input`. The 400 was not a timeout, so `/save`
  returned 500 and the bot failed to parse the error body.
- Fix: `get_response` takes a `json_mode` flag (off by default, sent as
  `NOT_GIVEN` instead of `null`). `digest()` turns it on and builds the input
  as the article followed by "Return the digest as JSON." Re-sending the same
  URL retried only the model (same ID, no re-fetch) and the item became
  `digested`. A new link (`go.dev/blog/defer-panic-and-recover`,
  `e96cbcd95fded5a1`) was then digested on the first try.
- Lesson: an eval result is not done until the chosen config is in the
  production code path.

### 2026-10-11: Medium-hosted blog returns 403

- `netflixtechblog.com` returns `http_403` (Cloudflare block page), also with a
  Chrome User-Agent. On 10/17 the `/feed` URL was tried: it returns XML, which
  `fetch_url` does not accept. Treated as a known limitation; no browser
  automation.

### 2026-10-18: Clean install failed (Python version and LangChain conflict)

- How it was found: the clean-terminal demo (`git clone`, new `.venv`,
  `pip install -r requirements.txt`). My own `.venv` was installed step by
  step, so it never hit this.
- Problem 1: `langchain==0.3.30` requires `langchain-core<1.0`, but
  `requirements.txt` pins `langchain-core==1.3.3`, so pip could not resolve
  the set.
- Problem 2: the new `.venv` used macOS system Python 3.9. 8 pinned packages
  have no Python 3.9 build (`langchain-core`, `langchain-openai`,
  `langchain-text-splitters`, `langsmith`, `orjson`, `requests`, `soupsieve`,
  `urllib3`), so pip reported "No matching distribution found".
- Fix:
  - Removed `langchain` from `requirements.txt`; `digest_langchain.py` now
    imports from `langchain_core` instead.
  - Installed Python 3.12 with Homebrew and built the `.venv` with
    `python3.12 -m venv .venv`. Install and demo then passed.
- Lesson: a `requirements.txt` from `pip freeze` is only proven by a fresh
  install on the documented Python version.

## Known failures and limits

- Medium-hosted blogs return 403 (Cloudflare bot protection).
- RSS/XML, PDF and other non-HTML content is rejected (`unsupported_content_type`).
- Pages over 2 MB are rejected (`too_large`).
- OpenAI errors other than timeout (400, rate limit, bad key) become a 500
  instead of `digest_failed`. The fetched text is already saved, so no data is lost.
- The bot does not check the HTTP status of `/save`. A 400/500 body
  (`{"detail": ...}`) is parsed as `SaveResponse`, so the reply is a Pydantic
  validation error instead of the `detail` message. Example: sending `hi`.
- Offline tests do not check that `digest()` turns on JSON mode or puts
  "json" in the input. The 10/17 regression was caught only by a real link.
- Digest retry only happens when the same URL is sent again; there is no
  retry limit.
- The bot keeps the Telegram `offset` in memory only. After a crash, the last
  message may be processed twice; this is safe because `/save` is idempotent.
- Timeout in `fetch_url` is per read, not total download time.
