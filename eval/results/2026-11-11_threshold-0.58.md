# 2026-11-11 Failure-cluster change: abstain threshold 0.6 -> 0.58 (dev only)

M2 check: "Identify one real failure cluster, make one change, rerun development evaluation
and record the outcome even if it gets worse."

## Failure cluster

No-evidence questions on a near topic do not abstain. Only failure left after 11/10:
q17 "How does QUIC's handshake work?" (no evidence) has top distance 0.585 < 0.6 and
matches DNS/UDP articles (see 2026-11-08_hybrid-failures.md).

## Change (one thing)

Retrieval-layer abstain threshold `max_distance` 0.6 -> 0.58. Nothing else changed.

- Code: `--max-distance` flag in `src/run_dev_eval.py` (commit `2136083`). Default stays 0.6.
  Production `/ask` (`answers.MAX_DISTANCE = 0.6`) is unchanged.
- Runs: `python src/run_dev_eval.py --search dense|hybrid --max-distance 0.58`
- Files: `2026-11-11_dev_{dense,hybrid}_eval_maxd0.58.{jsonl,run.json}`
- Same 30 dev cases (dataset sha256 unchanged), same corpus (2216 chunks). Final test not opened.

## Prediction (made before the run, from 11/10 distances)

Top distances above 0.5, sorted: q29 0.575 (answerable) < **q17 0.585 (no evidence)** <
**q10 0.590 (answerable)** < q16 0.629 (no evidence). q17 is closer than q10, so any threshold
in (0.575, 0.585] makes q17 abstain AND wrongly refuses q10. No single threshold can fix q17
without breaking q10.

Per-case diff vs 11/10 (same method):
- q17 abstained False -> True (fixed), both methods.
- q10 abstained False -> True (new error: Twilio question, gold item still rank 1), both methods.
- hybrid q19 / q29: items at ranks 3-5 changed order or one item swapped. Gold rank, top distance
  and abstention unchanged. Not caused by the threshold; likely small embedding-API variation
  changing RRF ties. Noted, not investigated.
- Retrieval quality (Hit@5, MRR) unchanged, as expected: only the abstain line moved.

Cost: about 423 embedding tokens per run (~$0.000008). No chat-model calls.

## Conclusion

- Worse trade, not a fix: one false abstention replaces one false answer. With 24 answerable
  vs 6 no-evidence cases, refusing a question I can answer is the worse error for a
  personal lookup tool.
- Distance alone cannot separate "near-topic, no answer" (q17) from "vague but answerable" (q10).
- Decision: keep `max_distance = 0.6`.
- Next fix belongs in the model layer (option B, moved to the improvement backlog after the trip):
  when the model says the context has no answer, `used_refs` must be empty. Check on the
  10-case Ask audit plus the 6 no-evidence dev cases.
